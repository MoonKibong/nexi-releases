NEXI

NEXI

읽기 안내 — 누가: 수행사 팀원과 고객 담당자 · 언제: 이 위키를 처음 열 때 · 읽은 뒤: 내 역할에 맞는 첫 문서를 골라 읽는다.

NEXI는 대보DX가 고객 프로젝트에서 AI coding agent와 함께 소프트웨어를 만드는 방법이다. 고객의 요청을 하루 안에 끝나는 작은 작업으로 나누고, agent가 만든 변경은 검사와 다른 agent의 리뷰를 거쳐 사람이 승인한 것만 받아들인다. 단계마다 누가 정하고 무엇을 남기는지가 정해져 있다.

시작하기

새 프로젝트를 시작한다면 함께 일하는 방식에 따라 고른다.

일하는 방식 안내
한 사람이 프로젝트를 맡는다 혼자 진행하기 — 요구사항을 받고 작업을 끝내는 순서.
여러 사람이 역할을 나눠 맡는다 팀으로 진행하기 — 각자 할 일과 다음 사람에게 넘기는 순서.

기존 코드를 고친다면 레거시 코드가 있는 저장소에서 시작하기를 읽는다. 새 시스템으로 옮긴다면 새 저장소로 시스템 옮기기를 함께 읽는다. 전환 가이드는 혼자 진행할 때와 팀으로 진행할 때 모두 쓴다.

키트 설치 방법은 키트 설치·배포 안내에 있다. 공개 다운로드는 아직 준비 중이다. 각 단계의 상세 절차는 시작하기에 있다.

직접 따라 해 보려면 혼자 CRM 만들어 보기나 다섯 명이 CRM 만들어 보기를 읽는다.

진행 중인 프로젝트에 합류했다면 맡은 일에서 시작한다.

  • PM은 착수 합의와 견적에서 범위를 합의하고, 백로그에서 작업과 담당을 정한다.
  • 개발자는 작업 순환에서 작업 하나를 받아 구현하고 리뷰에 넘긴다.
  • 검토자는 리뷰와 판정에 따른 처리를 따른다.
  • 고객 담당자는 요구사항과 끝내기에서 정할 내용과 결과를 확인하는 절차를 본다.

NEXI로 일하는 순서

고객과 만들 범위를 정하고, 하루 안에 끝낼 수 있는 작업으로 나눈다. 작업마다 완료 기준을 합의한 뒤 AI가 구현하고, 다른 AI가 코드와 검사 결과를 검토한다. 사람은 그 근거를 보고 변경을 반영할지 결정한다. 마지막에는 고객이 결과를 직접 확인한다.

순서 사람이 하는 일 남는 것
1. 요구 확인 고객, PM, FDE가 목표, 예외, 우선순위, 이번 범위를 정한다 요구사항 결정 문서, 아직 답이 없는 질문
2. 작업 계획 PM이 작업을 나누고 순서와 담당을 정한다 작업 이슈 목록과 선행 작업
3. 작업 준비 FDE가 작업의 완료 기준과 확인 방법을 쓰고 PM이 승인한다 작업 계약서
4. 구현 개발자가 agent에게 구현을 맡기고 결과를 읽는다 코드, 먼저 실패했다가 통과한 검사, 증거
5. 리뷰 구현하지 않은 agent가 리뷰하고, 검토자가 판정과 근거를 확인한다 판정 기록(APPROVE, REVISE, BLOCK)
6. 병합과 고객 확인 PM이 APPROVE된 변경을 병합하고, 고객이 결과를 써 보고 받아들인다 main의 commit, 최종 보고
7. 다음 작업 개선 팀이 막힌 이유와 걸린 시간을 보고 다음 계획을 고친다 실패와 고친 기록, 다음 이터레이션 계획
