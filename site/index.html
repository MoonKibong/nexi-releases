NEXI

읽기 안내 — 누가: 수행사 팀원과 고객 담당자 · 언제: 이 위키를 처음 열 때 · 읽은 뒤: 내 역할에 맞는 첫 문서를 골라 읽는다.

NEXI는 대보DX가 고객 프로젝트에서 AI coding agent와 함께 소프트웨어를 만드는 방법이다. 고객의 요청을 하루 안에 끝나는 작은 작업으로 나누고, agent가 만든 변경은 검사와 다른 agent의 리뷰를 거쳐 사람이 승인한 것만 받아들인다. 단계마다 누가 정하고 무엇을 남기는지가 정해져 있다.

진행 경로 고르기

상황 진행 가이드
혼자 새 프로젝트를 맡는다 혼자 진행하기 — 요구사항부터 독립 리뷰와 최종 확인까지.
팀이 역할을 나눠 일한다 팀으로 진행하기 — 역할, branch와 다음 사람에게 넘길 결과.
예전 시스템 옆에 새 시스템을 만든다 새 저장소로 시스템 옮기기 — 기준 고정, 비교 검사와 전환 작업.

명령의 입력·산출물·멈춤 조건은 skill 참조, 원문과 버전 확인은 공통 규칙에 있다.

바로 시작하기

  • 시작하기 — 요구사항을 받은 날부터 고객에게 넘기는 날까지 차례로 따라 한다.
  • 레거시 코드가 있는 저장소에서 시작하기 — 이미 돌아가는 코드를 고치거나 옮길 때 시작하기와 함께 읽는다.
  • NEXI 키트 내려받기 — 시작하기의 단계를 프롬프트로 진행하게 해 주는 skill 묶음이다.
  • 혼자 CRM 만들어 보기 · 다섯 명이 CRM 만들어 보기 (내부 문서) — CRM 요구사항 하나로 처음부터 끝까지 따라 해 보는 예제다.
  • 예전 CRM을 새 스택으로 옮겨 보기 (내부 문서) — 혼자와 팀 모두 다루는 예제다.

이 페이지에 나오는 말:

  • T# — 하루 안에 끝내고 검증할 수 있는 작업 하나. GitHub 이슈 번호로 부른다.
  • FDE — 고객 현장에서 결과를 책임지는 엔지니어. 요구사항을 분석하고 작업 계약서 초안을 쓴다.
  • 작업 계약서 — 작업 하나에서 만들 것, 하지 않을 것, 끝났다고 볼 기준, 확인 방법을 적은 문서. 사람이 승인해야 구현을 시작한다.
  • PR, SHA — PR은 코드 변경을 검토받아 합치는 요청이다. SHA는 commit 하나를 가리키는 고유 번호다.

다른 말의 뜻은 개념 참조에 있다.

어디서 시작하나

나는 먼저 읽을 곳 읽고 나면
이 방법을 처음 본다 시작하기 왜 이렇게 일하는지, 누가 언제 무엇을 정하는지 안다
프로젝트에 합류한 개발자다 작업 순환 작업 하나를 받아 구현하고 리뷰에 넘긴다
PM이다 시작하기, 착수 합의와 견적 요구사항과 작업 목록을 확정하고, 작업 계약서를 승인하고, 병합한다
검토자다(코드베이스 소유자가 지정한 사람) 작업 순환의 리뷰, 판정에 따라 변경을 승인할지, 고치라고 할지, 멈출지 정하고 근거를 남긴다
고객 담당자·결정권자다 킥오프 진행안, 판정 기준 프로젝트 동안 무엇을 결정해 달라는 요청을 받는지, 결과를 무엇으로 판단하는지 안다

요청 하나가 처리되는 과정

고객이 "지연 주문을 조회하는 화면이 필요하다"고 요청했다고 하자. 먼저 업무 규칙과 예외를 고객에게 묻고, 이번에 만들지 않을 것도 정한다. 그다음 하루 안에 끝나는 작업으로 나누고, 작업마다 작업 계약서를 써서 사람이 승인한다. agent가 구현하면 다른 agent가 리뷰하고, 통과한 변경만 main에 들어간다. 마지막에 고객이 결과를 써 보고 받아들이거나 보완을 요청한다.

순서 사람이 하는 일 남는 것
1. 요구 확인 고객, PM, FDE가 목표, 예외, 우선순위, 이번 범위를 정한다 요구사항 결정 문서, 아직 답이 없는 질문
2. 작업 계획 PM이 작업을 나누고 순서와 담당을 정한다 작업 이슈 목록과 선행 작업
3. 작업 준비 FDE가 작업의 완료 기준과 확인 방법을 쓰고 PM이 승인한다 작업 계약서
4. 구현 개발자가 agent에게 구현을 맡기고 결과를 읽는다 코드, 먼저 실패했다가 통과한 검사, 증거
5. 리뷰 구현하지 않은 agent가 리뷰하고, 검토자가 판정과 근거를 확인한다 판정 기록(APPROVE, REVISE, BLOCK)
6. 병합과 고객 확인 PM이 APPROVE된 변경을 병합하고, 고객이 결과를 써 보고 받아들인다 main의 commit, 최종 보고
7. 다음 작업 개선 팀이 막힌 이유와 걸린 시간을 보고 다음 계획을 고친다 실패와 고친 기록, 다음 이터레이션 계획

agent는 조사, 초안, 구현, 명령 실행을 맡는다. 범위 변경, 승인, 병합, 배포, 고객 인수와 위험 수용은 정해진 사람이 한다. 기본 주기는 2주이고 프로젝트 사정에 따라 고친다. 원칙과 전체 흐름은 시작하기에 있다.
