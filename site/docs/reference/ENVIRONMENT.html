환경 프로필

환경 프로필

읽기 안내 — 누가: 착수 합의를 하는 PM과 FDE · 언제: 고객의 개발 환경을 확인하고 NEXI로 할 수 있는지 판정할 때 · 읽은 뒤: 착수 합의에서 항목마다 값을 정하고 판정한다. 정한 값은 AGENTS.md에 남긴다.

NEXI는 어느 고객에게서나 같은 원칙으로 일한다. 고객마다 다른 것은 개발 환경이다. 협업 서비스, 쓸 수 있는 AI, 데이터를 밖으로 보내도 되는지 같은 것이다. 이 값을 고객마다 정해 두는 것이 환경 프로필이다. 원칙을 지킬 수 없는 환경이면 원칙을 빼지 않고, 그 고객에게는 적합하지 않다고 판정한다.

바뀌지 않는 원칙

원칙 환경이 내줘야 하는 것
요구사항, 작업 계약서와 디자인 기준, 최종 보고는 사람이 승인한다 승인을 기록할 저장소, 누가 승인했는지 가릴 계정
작업은 하루 이하이고, 선행 작업이 수용된 뒤 시작한다 이슈와 그 상태를 읽을 수 있는 협업 서비스
새 동작은 그 기준에서 먼저 실패하는 검사로, 이미 있던 동작은 기준선 실행과 함께 회귀 검사로 확인한다. 마지막 변경 뒤 모두 통과한다. 디자인 시스템 작업부터의 화면 작업은 승인된 디자인 기준과 스크린샷으로 확인한다 이 프로젝트의 검사를 돌릴 실행 환경, 화면 작업이면 브라우저
구현한 agent와 다른 agent가 읽기 전용으로 리뷰하고, 판정을 원문 그대로 기록한다 서로 다른 agent 둘, 리뷰 agent의 읽기 전용 실행
리뷰한 내용 그대로 main에 들어가고 이슈가 닫혀야 수용이다 리뷰한 head를 확인하며 병합하고 그 결과를 확인할 수 있는 협업 서비스
끝낼 때 새 사본에서 설치부터 검사까지 다시 돌린다 새 사본을 받아 돌릴 수 있는 환경
비밀 값은 저장소 밖에 둔다 저장소 밖에서 설정을 준비할 방법

예외는 하나다. 리뷰를 맡을 다른 agent를 쓸 수 없을 때(예: 사용 한도), 사람이 고르면 같은 agent가 따로 연 읽기 전용 세션에서 리뷰한다. 다만 데이터를 지우거나 덮어쓰는 변경, 권한과 역할을 바꾸는 변경, 기존 데이터를 옮기는 변경, 프로젝트 밖의 데이터나 서비스에 닿을 수 있는 명령은 같은 agent 리뷰로 수용하지 않는다. 다른 agent를 다시 쓸 수 있을 때까지 기다린다. 판정에 그 사실과 이유가 남는다.

고객마다 정하는 것

항목 값 어디에 정하나
방식 혼자, 팀 환경 프로필(Mode:)
협업 서비스 GitHub, 설치형 GitLab 환경 프로필(Forge:, Forge-Host:)
agent 조합 Claude Code 구현과 Codex 리뷰, 또는 그 반대 환경 프로필(Agents:)
데이터 반출 클라우드 AI에 코드와 문서를 보내도 되는가 환경 프로필(Data:)
네트워크 개발 PC가 협업 서비스, AI 서비스, 패키지 저장소에 닿는가 착수 합의에서 확인한다
스택과 외부 시스템 언어, 로컬과 외부 시스템 요구사항 결정 문서(요구사항)
모델 리뷰 모델(기본 gpt-6-astra), 구현 모델 각 도구의 설정. 판정과 증거에 실제로 쓴 모델이 남는다
agent 권한 각 도구의 권한 설정 각 사람이 자기 도구에서 정한다

정해져 있어 바꿀 수 없는 것도 있다.

  • 검사 명령의 이름: make build, make test, make lint, make screenshots. 프로젝트가 이 이름 아래 실제 명령을 묶는다.
  • 문서의 상태 표시와 차례 알림: 한국어(상태: 초안, 상태: 승인 등). 다른 언어는 지원하지 않는다.
  • 운영체제: macOS와 Linux. Windows로 돌린 기록은 없다.

환경 프로필 적기

착수 합의에서 정한 값을 /nexi-init에 넣으면 AGENTS.md에 적힌다. Mode:와 팀이면 PM: 줄은 "What this is" 다음에, 나머지는 ## 환경 절에 한 줄씩 들어간다.

/nexi-init <프로젝트 이름> [team] [forge=github] [agents=claude-code+codex] [data=cloud-ok]

넣지 않은 값은 기본값이다. 이미 있는 저장소에서는 /nexi-init이 AGENTS.md를 고치지 않으므로, 아래 절을 직접 더하고 저장소의 원래 절차로 main에 넣는다.

## 환경
Forge: github | gitlab
Forge-Host: <GitLab 주소. GitHub면 적지 않는다>
Agents: claude-code+codex | codex+claude-code
Data: cloud-ok | internal-only
  • 줄이 없으면 지금의 기본값이다. Forge: github, Data: cloud-ok이고, Agents:가 없으면 어느 쪽이 구현하든 다른 쪽이 리뷰한다.
  • 모든 skill이 시작할 때 이 절을 확인한다. 같은 줄이 둘이거나, 값이 비었거나, Forge:와 Data:가 목록에 없는 값이면 아무것도 바꾸지 않고 멈춘다. 고친 뒤 같은 프롬프트를 다시 넣는다.
  • Data: internal-only이면 모든 skill이 멈춘다. 지금 키트가 다루는 agent 조합은 모두 클라우드 AI를 쓰기 때문이다.
  • Agents:가 있으면 맡은 쪽이 아닌 agent가 구현이나 리뷰를 하려 할 때 멈춘다. 리뷰 agent를 쓸 수 없어 사람이 같은 agent 리뷰를 고른 경우는 허용한다. nexi-run은 claude-code+codex일 때만 돈다. 목록에 없는 Agents: 값이면 nexi-init, nexi-implement, nexi-review, nexi-run이 멈춘다(어댑터가 필요하다). 다른 skill은 그대로 돈다.
  • Forge: gitlab이면 어댑터(P#251)가 나오기 전까지 모든 skill이 멈춘다.

착수 합의에서 판정하기

항목마다 고객의 값을 정하고, 아래 표와 다음 절의 조합을 보고 넷 가운데 하나로 판정한다.

판정 뜻 다음
검증됨 그 값의 조합을 실제로 끝까지 돌린 기록이 있고, 빠진 단계가 없다 진행한다
지원하지만 검증 안 됨 키트가 그 값을 지원하지만 이 조합으로 끝까지 돌린 기록이 없거나, 기록에 빠진 단계가 있다(부분 검증) 고객에게 그대로 알리고, 첫 작업들을 검증으로 다룬다
어댑터가 필요하다 원칙에 필요한 것을 환경이 내줄 수 있지만, 키트가 그 값을 아직 다루지 못한다 어댑터 계획과 견적을 낸다. 어댑터가 나오기 전에는 시작하지 않는다
적합하지 않다 원칙에 필요한 것을 환경이 내줄 수 없다. 예: 판정을 기록할 저장소가 없다, 검사를 돌릴 환경이 없다 시작하지 않는다

데이터를 밖으로 보낼 수 없는 고객(Data: internal-only)에게는 지금 키트가 다루는 agent 조합이 모두 클라우드 AI를 쓴다. 그래서 agent 조합 항목이 "어댑터가 필요하다"가 된다.

검증된 조합

방식 협업 서비스 agent 조합 판정 기록
혼자 GitHub Claude Code 구현, Codex 리뷰 지원하지만 검증 안 됨(부분 검증) 새 프로젝트는 "혼자 CRM 만들어 보기" 예제대로 빈 저장소에서 최종 보고 승인까지 사람이 대화형으로 끝냈다. 둘러보기 결과 칸은 비어 있었고, 새 사본에서 실행 명령은 돌리지 않았으며(고객 수용으로 승인), 앞쪽 작업 일부는 이전 규칙으로 수용됐다. 작업 여덟 개는 같은 agent 리뷰를 받았다. 레거시 전환 예제(내부 문서 CRM_MIGRATION_RUN_RECORD)는 headless 실행으로 최종 보고 승인까지 했고, 앱을 띄워 써 보기, 끝내기의 스크린샷과 새 사본 검사 일부는 돌리지 않았다. 멈췄다 이어 하기, 디자인 변경, 끝내기 거절은 아직 돌리지 않았다
팀 GitHub Claude Code 구현, Codex 리뷰 지원하지만 검증 안 됨(부분 검증) 한 머신의 사본 다섯으로 인계, 리뷰, 병합을 확인했다. 사람마다 계정과 컴퓨터가 다른 실행과 끝내기까지 간 실행은 아직 없다. 그래서 PM만 할 수 있는 일을 다른 사람이 하려 할 때 멈추는지, main이 움직인 뒤 다시 리뷰하는지는 검증되지 않았다
혼자, 팀 GitHub Codex 구현, Claude Code 리뷰 지원하지만 검증 안 됨 Codex를 주 agent로. nexi-run은 쓸 수 없다
혼자, 팀 GitHub CuCu 구현 어댑터가 필요하다 지원 계획이 있다(P#275). 지금 키트의 환경 확인은 CuCu를 받지 않는다
혼자, 팀 설치형 GitLab 아무것 어댑터가 필요하다 어댑터 계획이 있다(P#251)
혼자, 팀 아무것 클라우드 AI를 쓰지 않는 조합 어댑터가 필요하다 없음
