참조

읽기 안내 — 누가: NEXI로 일하는 사람 · 언제: 이름 하나(skill, 파일, 개념, 규약)의 정확한 뜻과 규칙을 찾을 때 · 읽은 뒤: 아래에서 해당 문서를 열어 확인한다.

NEXI 키트

  • NEXI 키트 — 내려받기와 설치
  • skill 색인 — skill 열 개 중 지금 쓸 것을 고른다. 각 상세 페이지에 입력, 실행하는 사람, 명령, 산출물, 멈춤과 다음 차례가 있다.
  • skill 공통 규칙 — 설치된 원문과 버전, 환경, 승인, 원격 실패와 중단 뒤 재개.
  • 산출물 참조 — 요구사항 결정 문서, 작업 계약서, 디자인 기준, 증거, 판정 기록, 최종 보고, 이슈 본문의 줄
  • 개념 참조 — 원칙, 혼자와 팀, 역할, branch, 작업의 종류, 검증, 리뷰와 수용, 상태 줄, 재개
  • 환경 프로필 — 바뀌지 않는 원칙, 고객마다 정하는 것, AGENTS.md에 적는 법, 착수 합의에서 판정하는 법, 검증된 조합

skill별 상세

준비와 결정 구현과 마무리
nexi-init — 프로젝트 시작 nexi-implement — 구현과 증거
nexi-requirements — 요구사항 결정 nexi-review — 독립 리뷰와 기록
nexi-backlog — 작업과 담당 nexi-merge — 병합과 수용
nexi-contract — 작업 계약서 nexi-finish — 최종 확인
nexi-design — 화면 기준 nexi-run — 선택적인 반복 실행

진행 순서를 찾으면 혼자, 팀, 새 저장소 전환 중에서 고른다.

검증과 양식

  • 검증 명령 규약 — 검사가 갖출 조건, red 확인, 어느 계층에서 검사할지
  • 양식 — 기회 평가, 범위 합의, 주기 계획, 막힌 일, 측정, 실패, 인수인계, 아키텍처 결정 기록
  • NEXI 구현 패턴 — 인증, 권한, 데이터 격리처럼 되풀이되는 구현 문제의 계약과 테스트 조건. 패턴마다의 문서는 여기서 연다.

조건이 맞을 때만 쓰는 기법

  • Java Spring Boot 실행 프로필 — Java와 Spring Boot 저장소를 고칠 때
  • 온톨로지 참조 아키텍처 — 여러 팀이 같은 업무 개념을 다르게 다루거나, 여러 시스템의 식별자가 어긋날 때. 명세 양식은 온톨로지 명세 템플릿이다.

예전 하네스(make harness, team.sh)의 문서, prompt, 레인 문서, 용어 규약은 위키의 "프로젝트 기록"에 있다.
