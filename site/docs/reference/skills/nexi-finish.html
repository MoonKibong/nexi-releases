nexi-finish — 전체 검증과 최종 확인

읽기 안내 — 누가: 이 skill을 실행하거나 결과를 넘겨받는 사람 · 언제: 입력, 산출물과 멈춘 이유를 확인할 때 · 읽은 뒤: 알맞은 프롬프트를 넣고 다음 차례에 결과를 넘긴다.

시작 전에

  • 입력: 열린 task 이슈가 없고, 수용된 작업과 기존 이력이 확인된 깨끗한 main. FINAL 초안만 예외다.
  • 실행하는 사람: 팀은 PM이 실행한다. 사람이 앱을 써 보고 결과를 적고 최종 보고를 승인한다.
  • 공통 확인: 원문과 버전, 환경과 재개. 공개 키트 상태는 배포 안내에서 본다.

명령과 동작

새로 받은 사본에서 전체를 검증하고, 사람이 앱을 써 본 뒤 최종 보고서를 승인한다.

프롬프트 누가(팀) 하는 일
/nexi-finish PM 열린 작업이 없는지 확인하고, 새 사본에서 README 순서대로 설치부터 lint까지 돌린다. 이 폴더에서는 README가 정한 방법이 있으면 새 DB로 준비하고 앱을 이 컴퓨터에만 띄운다(포트가 쓰이고 있으면 바꿀지 묻는다). 결과, 패턴 예외, 둘러볼 목록을 docs/FINAL.md 초안에 적는다. commit하지 않는다
/nexi-finish reject <결함> PM 결함마다 작업 이슈를 만들고, 띄운 앱을 멈추고, 초안을 ~/nexi-final/에 저장한 뒤 작업 트리에서 지운다
/nexi-finish approve PM 둘러보기 목록의 모든 행에 사람이 적은 결과가 있어야 한다. 실패하거나 돌리지 않은 단계가 있으면 고객이 받아들였는지 묻는다. 승인한 docs/FINAL.md를 main에 넣는다

멈추는 경우

  • 열린 작업이 있다.
  • 작업 트리에 FINAL.md 말고 다른 변경이 있다.
  • main에 리뷰받지 않은 외부 commit이 있다(이미 있는 저장소에 팀 모드 들이기 6).
  • 둘러보기 목록에 빈 행이나 이상 있음이 있다(approve). 빈 행을 채우거나 reject한다.
  • 시험한 뒤 main이 움직였다(approve).

다음 차례

다음: 초안 뒤 사람이 앱을 써 보고 둘러보기 목록의 행마다 확인함, 이상 있음: <무엇>, 확인 안 함 가운데 하나를 적은 뒤 approve 또는 reject <결함 내용>. reject 뒤 /nexi-backlog next. approve 뒤에는 할 일이 없다.

실행 환경과 승인 범위

새 사본 검사는 원격에서 받은 파일과 README에 적힌 준비만 사용한다. 로컬 파일을 복사해 통과시키지 않는다. DB를 만드는 명령은 키트의 격리 실행기를 사용하고 버릴 수 있는 새 경로를 쓴다. 현재 폴더의 앱은 준비가 통과했을 때만 띄운다. 다른 작업의 포트나 프로세스는 그대로 두고, 포트 변경은 사람에게 묻는다.

실패·건너뜀·시간 초과·미실행 단계는 결과에 남는다. 사람이 이를 승인하려면 고객 결정권자의 이름·날짜·수용한 단계가 필요하다. 둘러보기의 빈 행이나 이상 있음은 승인할 수 없다. 확인 안 함은 미실행 단계로 다룬다. 보고를 쓰고 나서 새 작업이 열렸거나 main이 바뀌면 다시 끝내기를 한다.

reject는 검토 중인 초안의 결함을 작업으로 만든다. 이미 승인된 보고 뒤의 결함은 nexi-backlog change로 다룬다. 새 요구사항이면 먼저 요구사항을 정하고 승인받는다. 앱의 로컬 확인과 최종 보고 승인이 운영 배포를 뜻하지는 않는다.

남는 것

산출물 확인할 것
최종 보고 초안 docs/FINAL.md. 시험한 main, 명령별 결과, 빠진 단계, 둘러보기 결과를 담는다.
승인 결과 승인한 보고가 main에 들어간 commit. 혼자는 직접 push, 팀은 final-<commit> PR을 병합한다.
