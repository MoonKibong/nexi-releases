skill 공통 규칙

읽기 안내 — 누가: NEXI skill을 쓰는 사람 · 언제: 시작 조건, 승인 주체나 멈춘 뒤의 차례를 확인할 때 · 읽은 뒤: 원인에 맞는 사람과 프롬프트로 이어 간다.

원문과 버전

실행 절차는 설치된 키트의 nexi-*/SKILL.md와 그 파일이 가리키는 참조를 따른다. 이 설명과 설치된 키트가 다르면 원문을 기준으로 하고, 팀은 PM과 키트 버전부터 맞춘다. skill끼리 다른 버전을 섞지 않는다. 키트 버전은 nexi-init/KIT_VERSION, 받은 ZIP의 동일성은 SHA-256으로 확인한다. 공개 다운로드는 배포 안내에서 확인한다. 아직 공개 키트가 없으면 이 문서의 절차는 키트를 받은 뒤 진행한다.

입력과 환경

skill은 필요한 입력이 빠졌거나 파일·이슈를 읽을 수 없으면 무엇을 넣을지 알리고 멈춘다. 선택 입력을 생략하면 해당 skill의 기본값을 쓴다. 시작 전에 프로젝트의 AGENTS.md에 적힌 환경과 실행 agent도 확인한다. 지원하지 않는 forge·agent·데이터 정책이면 STOP 이유를 보이고 변경하지 않는다. 현재 사용할 조합은 환경 프로필에서 확인한다.

승인하는 사람과 남는 기록

단계 사람이 확인할 것 남는 기록
요구사항 승인 결정마다의 범위, 출처와 승인 상태 승인된 REQ-CONTEXT.md
작업 계약서 승인 산출물과 수용 기준, 검사, 적용 패턴 승인된 docs/contracts/T<N>.md
화면 기준 승인 디자인 시스템·변경 작업의 BRIEF 작업 계약서와 함께 승인된 BRIEF.md
구현과 리뷰 검사 결과, 현재 변경에 대한 다른 agent의 판정 증거와 docs/reviews/T<N>.md
병합과 수용 리뷰한 변경과 원격 main이 같은가 수용된 commit과 이슈의 NEXI 수용 기록
최종 확인 새 사본 검사와 사람이 앱을 써 본 결과 승인된 docs/FINAL.md

AI가 사람 대신 승인하지 않는다. 팀의 PM 권한은 원격 main의 AGENTS.md에 있는 PM: 줄로 확인한다. 요구사항이 바뀌어 작업 계약서의 기준 해시와 다르면 계약서를 다시 쓰고 승인받는다. 리뷰 뒤 변경이 바뀌면 다시 리뷰한다. 이슈가 닫힌 사실만으로 작업이 수용된 것은 아니다. 차이는 개념 참조에서 본다.

다음 차례와 이어 하기

skill의 답은 다음: 줄로 끝난다. 그 줄에서 프롬프트와 실행할 사람·도구를 확인한다. 예를 들어 다음 (PM)이면 PM에게 결과를 넘기고, 다음 (Codex, 읽기 전용)이면 리뷰하는 agent에서 실행한다. 이미 끝난 단계는 다시 만들지 않는다. 같은 프롬프트를 넣으면 쓰다 만 초안, 기록과 push가 끝나지 않은 commit을 확인해 이어 간다. 승인 직전에 내용이 바뀌었으면 새 내용을 보여 주고 다시 묻는다.

혼자는 작업의 구현과 리뷰 기록을 nexi-merge 때 commit한다. 요구사항 승인과 최종 보고 승인은 각 승인 단계에서 commit한다. 팀은 각 단계의 문서와 변경을 작업 branch에 commit·push하고 다음 차례를 이슈에 남긴다. nexi-finish의 최종 보고 초안은 commit하지 않는다. 같은 작업 branch는 한 번에 한 사람이 다룬다.

원격 명령이 실패하면

확인 결과 사람이 할 일
NOT_LOGGED_IN 로그인 절차를 마친 뒤 같은 프롬프트를 다시 넣는다.
BLOCKED 샌드박스의 네트워크·키체인 접근을 승인하거나, 안내받은 명령을 자기 터미널에서 실행한다.
OK 로그인 문제가 아니다. 실패한 명령의 오류와 필요한 입력을 확인한다.

같은 원격 오류 때문에 로그인을 되풀이하지 않는다. skill은 stash, reset, clean, rebase, force push로 막힌 상태를 정리하지 않는다.

BLOCK 또는 세 번째 연속 REVISE

사람이 원인을 정할 때까지 작업이 멈춘다. 팀은 PM이 이슈에 결정과 다음 사람을 남긴다. 혼자는 다음 프롬프트에 결정을 넣는다. 작업 순환의 막힘 처리를 따른다.

원인 다음 경로
계약서 개발자가 작업을 보존하고 담당 FDE에게 수정을 넘긴다. 담당자이면 직접 초안을 쓴다. 승인 뒤 구현을 이어 간다.
디자인 디자인 변경을 만들고, 이를 기다리도록 작업을 나눈다.
크기 작업을 나누고 새 작업은 main에서 시작한다.
요구사항 요구사항을 다시 정하고 승인한 뒤 계약서를 고친다.
리뷰 독립성 다른 agent가 같은 변경을 리뷰한다.

세 번째나 네 번째 REVISE에서 검토자가 앞선 지적이 모두 해결됐고 새 지적만 있다고 보고 원인 후보: 계속을 적을 수 있다. 사람이 그 판정 하나에 한해 계속하도록 정한다. 연속 횟수는 초기화하지 않고, 다섯 번째 REVISE와 BLOCK에는 계속 경로가 없다.
