nexi-implement — 계약서대로 구현

nexi-implement — 계약서대로 구현

읽기 안내 — 누가: 이 skill을 실행하거나 결과를 넘겨받는 사람 · 언제: 입력, 산출물과 멈춘 이유를 확인할 때 · 읽은 뒤: 알맞은 프롬프트를 넣고 다음 차례에 결과를 넘긴다.

시작 전에

  • 입력: 승인된 계약서와 그 계약서가 가리키는 승인된 REQ-CONTEXT. 화면 작업은 승인된 BRIEF도 준비한다.
  • 실행하는 사람: 개발자가 구현하고 검증한다.
  • 공통 확인: 원문과 버전, 환경과 재개. 공개 키트 상태는 배포 안내에서 본다.

명령과 동작

승인된 계약서대로 구현하고, 검사 결과를 증거 파일에 남긴다. 리뷰 지적을 고칠 때도 같은 프롬프트를 쓴다.

프롬프트 누가(팀) 하는 일
/nexi-implement <N> 개발자 새 검사가 실패하는 것을 먼저 보고, 구현한 뒤 모든 검사를 통과시킨다. 화면 작업이면 계약서가 정한 제목이나 상태 제목이 보이는지 확인한 뒤 스크린샷을 찍는다. 결과는 docs/evidence/T<N>.md에 적는다. 혼자면 commit하지 않고, 팀은 commit과 push를 하고 PR을 연다

새 검사는 수용 기준의 단정 때문에 실패해야 한다. import·컴파일 오류나 시간 초과는 red가 아니다. 마지막 변경 뒤 새 검사와 회귀 검사가 모두 통과해야 한다.

구현 전부터 통과하는 검사는 그 동작이 이미 있다는 뜻이다. 일부러 실패하게 만들지 않고 regression으로 적는다.

멈추는 경우

  • 계약서가 승인되지 않았거나, 계약서를 쓴 뒤 요구사항이 바뀌었다.
  • 화면 작업인데 BRIEF가 승인되지 않았다. 단, 계약서의 ## 화면에 디자인 시스템보다 앞선 작업으로 기록된 경우는 제외한다.
  • 승인한 계약서대로 끝낼 수 없다(리뷰 지적이든, 구현하거나 main을 병합하다 드러났든). 계약서를 다르게 읽고 진행하지 않는다. 작업을 남기고(팀은 commit과 push), 이슈 담당자면 nexi-contract로 고친 초안을 쓴다. 담당자가 아니면 FDE 차례 댓글을 단다.
  • 리뷰가 BLOCK이거나 REVISE가 세 번 이어졌다. 사람(팀은 PM)이 원인을 정할 때까지 멈춘다. 원인이 계약서이면 팀은 PM의 결정: 계약서 — 개발자 차례 댓글, 혼자면 프롬프트 다음 줄의 결정: 계약서가 있을 때만 이어 간다.
  • 이 작업과 관계없는 변경이 있거나, merge 충돌이 작업 범위 밖이다.

다음 차례

다음: 혼자면 Codex를 읽기 전용으로 열고 nexi-review skill로 T#<N>을 리뷰해라.를 넣는다(Codex가 구현했으면 Claude Code로). 팀이면 /nexi-review <N> prepare.

팀의 main 반영: refresh

/nexi-implement <N> refresh는 다른 작업이 병합돼 뒤처진 리뷰 대기·승인 작업에 새 origin/main을 합친다. nexi-merge가 자동으로 부르거나 PM·해당 개발자가 실행한다. 새 기능과 새 검사는 만들지 않는다.

  • 대상은 STALE_BASE이고, 리뷰를 기다리거나 마지막 APPROVE 이후 판정 기록만 추가된 작업이다.
  • 승인된 계약서와 요구사항 연결이 그대로여야 한다. 계약서 범위 밖 충돌은 개발자에게 돌려보낸다.
  • README 순서로 설치·준비한 뒤 모든 계약 검사와 회귀 검사를 다시 돌린다. 화면 PNG도 다시 찍는다.
  • red와 기존 베이스라인은 보존하고 snapshot:, base:와 ## main 반영을 새 결과로 쓴다.
  • 충돌을 해결한 agent는 implemented by: 목록에 추가한다. 새 리뷰는 그 agent와도 달라야 한다.
  • 원격 작업 head나 main이 바뀌면 그대로 승인됐다고 보지 않는다. 결과에 따라 다시 반영하거나 개발자에게 넘긴다.

중단된 반영은 같은 명령으로 이어 간다. 일반 구현 중인 변경이 남았으면 refresh는 바꾸지 않고 일반 구현으로 안내한다. 성공 뒤에는 검토자가 /nexi-review <N> prepare로 새 변경을 리뷰한다.

남는 것

산출물 확인할 것
증거 docs/evidence/T<N>.md. 기준 commit, 검사 대상, 명령별 결과와 구현 agent를 남긴다.
화면과 코드 화면 작업은 마지막 변경의 PNG를 남긴다. 혼자는 미커밋 변경, 팀은 t<N>의 commit과 PR로 넘긴다.
