nexi-review — 독립 리뷰와 판정 기록

읽기 안내 — 누가: 이 skill을 실행하거나 결과를 넘겨받는 사람 · 언제: 입력, 산출물과 멈춘 이유를 확인할 때 · 읽은 뒤: 알맞은 프롬프트를 넣고 다음 차례에 결과를 넘긴다.

시작 전에

  • 입력: 작업 계약서, 증거, 변경 파일과 화면 PNG. 팀은 prepare가 정한 commit과 폴더에서 리뷰한다.
  • 실행하는 사람: 구현하지 않은 agent가 리뷰하고 검토자가 판정을 기록한다.
  • 공통 확인: 원문과 버전, 환경과 재개. 공개 키트 상태는 배포 안내에서 본다.

명령과 동작

구현하지 않은 agent가 읽기 전용으로 리뷰하고, 그 판정을 기록한다.

프롬프트 누가(팀) 하는 일
nexi-review skill로 T#<N>을 리뷰해라. 리뷰 agent 수용 기준마다 코드와 증거를 보고, 화면이면 스크린샷을 BRIEF와 대조한다. 코드 표준이 있으면 변경을 표준의 절마다 대조하고, 증거의 ## 넘겨받는 일이 수용 기준과 구현에 있는지 본다. APPROVE, REVISE, BLOCK 중 하나를 낸다. 파일을 바꾸지 않고 검사도 돌리지 않는다
/nexi-review <N> prepare 검토자(팀) 리뷰할 commit을 받고 리뷰할 agent를 고르게 한다. 리뷰를 백그라운드로 돌려 판정을 자동으로 기록하거나, 리뷰 프롬프트를 클립보드에 복사한다
/nexi-review <N> record 검토자 붙여 넣은 판정의 형식을 검사하고 docs/reviews/T<N>.md에 덧붙인다. 팀은 commit과 push를 하고 PR에 댓글을 단다
/nexi-review <N> confirm 검토자(팀) 개발자가 직접 기록한 APPROVE(nexi-run 등)를 검토자가 확인하고 이슈에 PM 병합 차례를 알린다

리뷰 agent는 구현한 agent와 달라야 한다. Claude Code가 구현했으면 Codex, Codex가 구현했으면 Claude Code가 리뷰한다. 팀의 prepare는 구현하지 않은 CuCu도 고를 수 있다. 같은 agent밖에 없으면 멈추고 묻는다. 사람이 이유와 함께 명시적으로 고르면 키트가 여는 새 읽기 전용 세션으로 리뷰한다. 모델이나 같은 agent 리뷰로 자동 전환하지 않는다.

같은 agent 리뷰로는 다음 변경을 수용할 수 없다. 해당하면 BLOCK으로 위험 범주와 파일 위치를 적는다.

  • 데이터를 지우거나 덮어쓰거나 초기화한다. seed·reset·깨끗한 사본 script도 포함한다.
  • 인증·권한·역할 또는 역할이 읽거나 고칠 수 있는 범위를 바꾼다.
  • 기존 데이터를 이전한다.
  • 프로젝트 밖 데이터나 서비스에 닿는 명령을 실행한다.

이 BLOCK은 코드나 계약서를 바꾸라는 뜻이 아니다. 다른 agent를 쓸 수 있게 되면 같은 변경을 다시 리뷰한다.

판정은 그때의 코드와 증거, base에만 해당한다. 리뷰 중 파일이 바뀌면 새로 준비한다. 기록할 때는 키트가 허용한 붙여 넣기 형식 보정만 하고 판정의 내용은 고치지 않는다.

판정 기준:

  • BLOCK: 사람이 정해야 할 것이 있다. 예: 계약서가 승인되지 않았거나 계약서를 쓴 뒤 요구사항이 바뀌었다. 판정은 사람이 정할 것(항목마다 원인 후보)과 결정 뒤 고칠 것을 나눠 적는다. 정할 것이 없으면 REVISE다.
  • REVISE: 기준이 충족되지 않았다. 증거나 스크린샷이 없거나 낡았다. 새 검사가 기준이 아닌 다른 이유로 실패했다.

멈추는 경우

  • 리뷰하는 사이 파일이 바뀌었다.
  • 판정이 형식 검사를 통과하지 못했다(record).

다음 차례

다음: 리뷰 agent의 판정을 붙여 /nexi-review <N> record로 기록한다(prepare에서 백그라운드 리뷰를 골랐으면 자동으로 기록된다). 기록 뒤 APPROVE면 /nexi-merge <N>(팀에서 개발자가 기록했으면 먼저 confirm). REVISE면 /nexi-implement <N>. BLOCK이나 연속 세 번째 REVISE면 사람(팀은 PM)이 원인을 정한다. 원인별 다음 차례는 작업 순환에 있다.

남는 것

산출물 확인할 것
판정 docs/reviews/T<N>.md에 현재 변경과 base를 묶은 판정을 추가한다.
팀 전달 PR과 이슈에 다음 차례가 남는다. 개발자가 기록한 APPROVE는 다른 검토자의 confirm을 거친다.
