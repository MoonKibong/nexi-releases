nexi-merge — 병합과 작업 수용

읽기 안내 — 누가: 이 skill을 실행하거나 결과를 넘겨받는 사람 · 언제: 입력, 산출물과 멈춘 이유를 확인할 때 · 읽은 뒤: 알맞은 프롬프트를 넣고 다음 차례에 결과를 넘긴다.

시작 전에

  • 입력: 현재 변경 전체를 덮는 완전한 APPROVE, 그 판정과 같은 증거·파일·base.
  • 실행하는 사람: 팀은 PM만 병합한다. 혼자는 본인이 판정과 증거를 읽고 진행한다.
  • 공통 확인: 원문과 버전, 환경과 재개. 공개 키트 상태는 배포 안내에서 본다.

명령과 동작

APPROVE된 작업을 main에 넣고 이슈를 닫는다.

프롬프트 누가(팀) 하는 일
/nexi-merge <N> PM 혼자면 작업 파일만 commit해 push하고, 팀이면 PR을 squash 병합한다. 수용 조건을 모두 통과하면 이슈에 NEXI 수용 댓글을 달고 닫는다

혼자 작업하며 판정을 아직 기록하지 않았으면 APPROVE 판정을 함께 붙여 넣는다. 병합한 뒤 수용 조건이 깨지면 이슈를 다시 열고 PM이 정한다. 팀에서는 이 병합으로 뒤처진 리뷰 대기 작업과 승인된 작업에 /nexi-implement <M> refresh를 이어서 돌린다. 각 작업의 승인된 계약서 안에서 새 main을 합치고 검사와 증거를 다시 만든다.

멈추는 경우

  • 마지막 판정이 APPROVE가 아니다.
  • 리뷰 뒤 코드나 계약서가 바뀌었다(새 리뷰가 필요하다).
  • 리뷰 뒤 main이 앞서 나갔다(개발자가 /nexi-implement <N>을 다시 하고 새 리뷰를 받는다).
  • 이 작업과 관계없는 파일이 있다.

다음 차례

다음: /nexi-backlog next. 열린 작업이 없으면 /nexi-finish.

수용할 변경의 동일성

혼자는 리뷰한 base를 부모로 하는 commit 하나에 리뷰한 파일과 추가된 판정 기록만 넣는다. 팀은 리뷰한 commit 뒤에 판정 기록만 추가됐는지 본다. PM이 그 head와 같은 트리를 리뷰한 base 위에 squash 병합한다. 리뷰 뒤의 merge commit이나 코드 변경은 새 리뷰가 필요하다.

이슈를 닫기 전에 원격 main에 정확한 변경이 들어갔는지 검사한다. 나눔·취소로 닫힌 작업은 수용이 아니다. 검사가 실패하면 수용으로 처리하지 않고 해시와 실패 조건을 보여 준다. 중단된 병합은 같은 명령으로 이어 간다.

팀의 자동 반영은 승인된 계약서 범위 안에서 임시 사본으로 한다. CuCu 병합, 검사 실패나 범위 밖 충돌은 개발자에게 넘긴다. 다른 반영이 잡고 있는 작업은 실행 이름을 보이며 멈춘다. PM은 기존 실행이 끝난 사실을 확인한 뒤 인계를 정한다.

남는 것

산출물 확인할 것
수용 기록 원격 main의 commit과 이슈의 NEXI 수용 댓글, 닫힌 이슈.
팀 후속 작업 다른 작업마다 main 반영 성공, 개발자에게 반환, 상태 확인 필요 또는 건너뜀을 알린다.
