nexi-run — 구현과 리뷰 반복

읽기 안내 — 누가: 이 skill을 실행하거나 결과를 넘겨받는 사람 · 언제: 입력, 산출물과 멈춘 이유를 확인할 때 · 읽은 뒤: 알맞은 프롬프트를 넣고 다음 차례에 결과를 넘긴다.

시작 전에

  • 입력: 승인된 작업 계약서와 nexi-implement의 입력, 사용할 수 있는 Codex 리뷰 환경.
  • 실행하는 사람: Claude Code에서 개발자가 실행한다. Codex가 구현한 작업은 일반 nexi-review 경로를 쓴다.
  • 공통 확인: 원문과 버전, 환경과 재개. 공개 키트 상태는 배포 안내에서 본다.

명령과 동작

구현, 리뷰, 판정 기록을 한 번에 돌린다. Claude Code에서만 쓴다.

프롬프트 누가(팀) 하는 일
/nexi-run <N> 개발자 nexi-implement 규칙으로 구현하고, Codex(gpt-6-astra)가 읽기 전용으로 리뷰한 판정을 기록한다. 첫째와 둘째 REVISE면 고치고 다시 리뷰받는다. 병합은 하지 않는다

멈추는 경우

  • APPROVE, BLOCK, 연속 세 번째 REVISE가 나왔다. 시작할 때 기록된 마지막 판정이 지금 파일에 그대로 해당하고 이 셋 가운데 하나여도 구현하지 않고 그 판정을 보여 준다.
  • Codex가 실패하거나 시간이 초과됐거나 판정이 아닌 답을 냈다.

다음 차례

다음: APPROVE면 판정과 증거를 읽은 뒤 /nexi-merge <N>(팀은 먼저 검토자가 /nexi-review <N> confirm).

중단과 재개

같은 명령은 현재 파일에 여전히 맞는 마지막 판정을 먼저 읽는다. APPROVE면 구현을 되풀이하지 않고 증거를 보여 준다. 낡은 판정은 더 이상 맞지 않는 이유를 보인다. 리뷰의 실패·시간 초과·판정 형식 오류는 결과를 보여 주고 멈춘다. 리뷰가 실행되는 동안 끝날 때까지 기다리고, 판정 기록을 건너뛰지 않는다.

같은 agent 리뷰는 리뷰 참조의 사람 선택과 위험 제한을 따른다. 세 번째·네 번째 REVISE의 한정된 계속 결정은 공통 규칙을 따른다. 다섯 번째 REVISE와 BLOCK은 사람이 다음 차례를 정한다.

남는 것

산출물 확인할 것
구현과 판정 nexi-implement의 증거와 nexi-review의 판정 기록이 남는다.
멈춘 상태 APPROVE여도 병합하지 않는다. 판정과 증거를 읽은 뒤 다음 사람에게 넘긴다.
