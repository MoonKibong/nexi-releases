nexi-init — 프로젝트 시작

읽기 안내 — 누가: 이 skill을 실행하거나 결과를 넘겨받는 사람 · 언제: 입력, 산출물과 멈춘 이유를 확인할 때 · 읽은 뒤: 알맞은 프롬프트를 넣고 다음 차례에 결과를 넘긴다.

시작 전에

  • 입력: 프로젝트 이름, 요구사항 원문 또는 읽을 수 있는 파일 경로. 팀이면 팀원 GitHub 계정도 준비한다.
  • 실행하는 사람: 혼자는 본인, 팀은 PM. 환경 프로필은 착수 합의에서 정한 값을 쓴다.
  • 공통 확인: 원문과 버전, 환경과 재개. 공개 키트 상태는 배포 안내에서 본다.

명령과 동작

저장소를 만들고 작업 규칙을 세운다.

프롬프트 누가(팀) 하는 일
/nexi-init <이름> + 요구사항 본인 비공개 GitHub 저장소, AGENTS.md(작업 규칙), docs/ 폴더, Makefile, README.md를 만들고 요구사항을 docs/requirements/REQUEST.md에 저장한다. 첫 commit을 push한다. 키트가 만들지 않은 이력이 있으면 그것을 검토할 작업을 안내한다
/nexi-init <이름> team + 요구사항 PM 위와 같고, AGENTS.md에 팀 규칙과 PM: 줄을 더하고 팀원을 초대한다
/nexi-init clone 누구나 지금 폴더 옆에 저장소를 새로 받는다(<이름>-2). 작업을 나눈 뒤나 nexi-finish reject 뒤에 쓴다

착수 합의에서 정한 forge=, agents=, data=를 함께 넣을 수 있다(환경 프로필).

멈추는 경우

  • git이나 gh가 없다.
  • GitHub의 main에 이 skill이 만들지 않은 이력이 있고 로컬과 다르다.

이미 있는 파일은 덮어쓰지 않고 알린다.

다음 차례

다음: /nexi-requirements analyze. 팀이면 팀원이 초대를 받고 git clone한다. clone 뒤에는 새 폴더에서 하려던 프롬프트를 넣는다.

남는 것

산출물 확인할 것
저장소와 규칙 비공개 GitHub 저장소, task·plan 라벨, AGENTS.md와 CLAUDE.md 링크
요구 원문 docs/requirements/REQUEST.md에 원문을 보존한다.
작업 폴더 docs/와 Makefile, README.md, 검증을 돕는 프로젝트 파일. 앱 구현은 골격 작업에서 시작한다.

함께 읽기

  • skill 색인 · 개념 참조
  • 실행 원문: nexi-init/SKILL.md. 설치된 키트의 같은 파일을 기준으로 한다.
