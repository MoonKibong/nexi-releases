비용과 시간 기록하기

읽기 안내 — 누가: PM과 Practice Lead · 언제: 고객과 측정하기로 합의했을 때, 비용 대비 효과를 보고하기 전, 팀을 늘릴지 정할 때 · 읽은 뒤: 작업마다 같은 범위로 시간과 비용을 적고, 비교 기준과 신뢰 수준을 붙여 보고한다.

NEXI 키트는 시간과 비용을 재지 않는다. 고객과 측정하기로 했으면 사람이 작업마다 적는다.

측정한다

  1. 비교할 기준부터 정한다. 어떤 종류의 작업을 비교할지, 무엇을 끝났다고 볼지(수용)를 정해 두고 바꾸지 않는다. 과거 실적이나 같은 기간의 비교 대상으로 기준선을 만든다. 둘 다 없으면 사전 추정을 따로 적고 기준선이 아니라고 표시한다.
  2. 작업마다 같은 항목을 적는다. 측정 기록 양식을 쓴다.
    • 이슈를 연 때부터 수용까지의 시간
    • 개발자와 검토자가 들인 시간(따로)
    • 기다린 시간
    • REVISE로 다시 한 작업
    • agent 비용
    • 품질 결과(첫 리뷰에서 통과했는지, 결함)
  3. 주기(기본 2주)마다 모은다. 수용한 작업 수, 첫 리뷰에서 통과한 비율, 작업 하나당 리뷰 시간. 이 값이 견적의 식에 들어간다.
완료한 작업의 비용 = 개발자 시간 비용 + 검토자 시간 비용 + agent 비용 + 공통 운영 비용

agent 비용은 쓴 만큼 내는 서비스면 청구된 금액이고, 직접 운영하면 쓴 시간에 합의한 시간당 단가를 곱한 값이다. 토큰 수는 참고만 한다. 시간으로 잰 비용과 섞어 두 번 세지 않는다. 항목별 입력값과 단가는 원가 모델(COST_MODEL.md, 내부 문서)에 있다. 고객 데이터와 상용 단가는 밖으로 내는 결과에 넣지 않는다.

숫자가 부풀지 않게 한다

위험 막는 방법
작고 쉬운 작업만 골라 수를 부풀린다 작업 유형, 범위 변경, 대표 표본을 함께 보인다
실패를 나중에 다른 것으로 분류한다 판정 기록과 분모를 그대로 보존한다
리뷰 시간을 빼서 agent 효율을 과장한다 개발자, 검토자, 대기, 재작업 시간을 따로 적는다
다른 종류의 작업과 비교한다 무엇이 같은지와 신뢰 수준을 보고한다
토큰 절감이 목표가 된다 수용, 재작업, 사람 시간, 보안 결과를 함께 본다

보고한다

"AI가 N% 빨랐다"고 하지 않는다. 무엇을 수용했는지, 어떤 증거가 있는지, 무엇이 미판정(아직 판단할 수 없음)이거나 미달인지, 어떤 제약이 있는지, 다음에 정할 일의 선택지가 무엇인지 보고한다. 비율에는 분모, 표본, 신뢰 수준을 붙인다. 기준선이 없으면 비용 효과는 "미판정"이다. 신뢰 수준이 낮은 수치를 목표나 보상에 연결하지 않는다.

팀을 늘리기 전에는 세 가지를 본다. 팀마다 따로 돌릴 수 있는 검사가 있는가, 서로 같은 파일을 덜 건드리게 나눌 수 있는가, 측정값으로 계산한 리뷰 처리량이나 전담 검토자가 있는가. 하나라도 없으면 새 팀은 일을 빠르게 하기보다 기다림과 서로 맞추는 비용을 늘리기 쉽다.
