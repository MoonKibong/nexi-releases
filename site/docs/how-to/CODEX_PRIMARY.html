Codex를 주 agent로 쓰기

Codex를 주 agent로 쓰기

읽기 안내 — 누가: Codex로 구현하려는 FDE나 개발자 · 언제: Claude Code 대신 Codex에서 구현할 때 · 읽은 뒤: Codex로 구현하고, Claude Code의 읽기 전용 세션에서 리뷰받는다.

NEXI 키트는 Claude Code와 Codex 양쪽에 설치된다(준비). 구현은 어느 쪽에서 해도 되지만, 리뷰는 구현하지 않은 쪽이 한다. Codex가 맡을 수 있는 것은 구현(nexi-implement)과 읽기 전용 리뷰(nexi-review)다. 요구사항, 백로그, 작업 계약서, 판정 기록, 병합, 끝내기와 nexi-run은 Claude Code에서 한다.

순서

  1. Claude Code에서 작업 순환의 1~2처럼 작업을 고르고 작업 계약서를 승인한다.
  2. 같은 폴더에서 Codex를 열고 구현을 맡긴다.
nexi-implement skill로 T#<N>을 구현해라.

증거 파일 docs/evidence/T<N>.md의 implemented by: 줄에 Codex와 모델이 적혔는지 본다. 이 줄을 보고 누가 리뷰할지 정해진다.

  1. 터미널을 하나 더 열어 Claude Code를 읽기 전용으로 연다. 혼자 하면 같은 폴더, 팀이면 /nexi-review <N> prepare가 알려 준 폴더에서 연다.
claude --permission-mode plan

그리고 리뷰를 맡긴다. 팀이면 prepare가 보여 준 줄(… 리뷰할 commit은 <해시>다.)을 그대로 넣는다. 파일을 바꾸겠다는 요청은 거절한다.

nexi-review skill로 T#<N>을 리뷰해라.
  1. 판정은 리뷰한 세션이 아닌, 파일을 쓸 수 있는 Claude Code 세션에서 기록한다. /nexi-review <N> record 다음 줄에 판정을 붙여 넣는다. REVISE면 Codex에서 다시 구현하고, APPROVE면 Claude Code에서 /nexi-merge <N>을 넣는다.

GitHub 명령이 실패할 때

Codex는 샌드박스 안에서 돌기 때문에 네트워크나 키체인이 막힐 수 있다. 그러면 Claude Code에서는 되던 gh나 git push가 로그인이 안 된 것처럼 실패한다. 이때 skill은 nexi-gh-check.sh로 원인을 가리고, 결과에 따라 다르게 한다.

결과 뜻 skill이 하는 일
OK 로그인돼 있고 GitHub에 닿는다 저장소, 권한, 거절된 push처럼 명령 자체의 문제로 본다. 다시 로그인하지 않는다
NOT_LOGGED_IN 로그인이 안 됐다 사람에게 자기 터미널에서 gh auth login을 하게 하고, 실패한 명령을 한 번 다시 한다
BLOCKED 샌드박스가 막았을 가능성이 크다 다시 로그인하지 않는다. 샌드박스 밖에서 실행해도 되는지 묻고, 안 되면 사람이 자기 터미널에서 돌릴 명령을 준다

명령을 받았으면 자기 터미널에서 돌리고 끝났다고 알려 준다. skill이 다음 단계부터 이어 간다. 같은 실패로 로그인을 되풀이하지 않는다. 규칙 원문은 공통 규칙에 있다.

Codex가 구현하고 리뷰도 해야 할 때

Codex가 구현한 작업은 Claude Code가 리뷰한다. Claude Code를 쓸 수 없는 급한 경우(예: 사용량 한도)에만, 사람이 정해서 Codex가 리뷰할 수 있다. 구현한 세션과 다른 새 세션에서 읽기 전용으로 하고, 되도록 구현한 모델보다 상급 모델을 쓴다. 판정의 reviewer: 줄에 같은 agent가 리뷰했다는 것과 그 이유가 남는다. 다만 데이터를 지우거나 덮어쓰는 변경, 권한과 역할을 바꾸는 변경, 기존 데이터를 옮기는 변경, 프로젝트 밖의 데이터나 서비스에 닿을 수 있는 명령은 같은 agent 리뷰로 수용하지 않는다. 다른 agent를 다시 쓸 수 있을 때까지 기다린다.
