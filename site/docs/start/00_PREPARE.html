준비

준비

읽기 안내 — 누가: 프로젝트에 참여하는 모든 사람 · 언제: 프로젝트를 시작하기 전, 키트가 새로 나왔을 때 · 읽은 뒤: 자기 컴퓨터에 키트와 도구를 갖추고 프로젝트 시작으로 간다.

각자의 컴퓨터에 Claude Code, Codex, NEXI 키트가 있어야 한다.

예제로 따라 해 보려면 CRM 예제의 1인 Step 0이나 5인 Step 0을 본다.

준비물

  • Claude Code와 Codex. 둘 다 로그인해 둔다. 보통 Claude Code가 문서와 코드를 쓰고 Codex가 리뷰한다.
  • GitHub 계정. 저장소와 작업 이슈를 GitHub에 둔다. 키트는 GitHub에서만 동작한다. GitLab 같은 다른 서비스는 아직 지원하지 않는다. GitHub CLI(gh)는 프로젝트 시작에서 AI가 확인하고, 없으면 설치와 로그인을 돕는다.
  • 브라우저. 로그인하고 앱을 써 볼 때 쓴다.

Node.js나 pnpm 같은 런타임과 패키지 관리자는 지금 설치하지 않는다. 요구사항 단계에서 기술 스택을 정한 뒤, 첫 작업(골격)이 정한 버전으로 설치한다.

키트 설치

NEXI 키트에서 nexi-kit.zip을 내려받고, 사용할 agent에게 다음과 같이 요청한다.

Claude Code를 쓰면 이렇게 넣는다.

~/Downloads/nexi-kit.zip 안의 INSTALL.txt를 읽고 그대로 설치해라.

cucu를 쓰면 이렇게 넣는다.

주의: cucu에서는 시스템 예약어(/)와의 충돌을 방지하기 위해 접두사로 !를 사용한다. 지금 키트는 CuCu를 agent로 받지 않아 skill이 첫 환경 확인에서 멈춘다. 지원은 준비 중이다(P#275).

~/Downloads/nexi-kit.zip을 ~/.cucu/skills/ 경로에 압축 해제하고, 앞으로 !nexi- 로 시작하는 명령어를 입력하면 이 경로의 파일을 읽고 지침에 따라 수행하도록 설정해라.

AI가 zip의 SHA-256, 키트 버전, 비교 표를 보여 준다. SHA-256은 받은 키트 파일이 같은지 확인하는 값이고, 키트 버전은 작업 증거와 최종 보고에 적히는 값이다. 비교 표는 skill 열 개가 Claude Code(~/.claude/skills)와 Codex(~/.codex/skills) 두 곳에 제대로 설치됐는지 보여 준다. CuCu를 써도 리뷰하는 Codex에는 키트가 필요하다. 그래서 먼저 Claude Code나 Codex에 위의 INSTALL.txt 프롬프트를 넣어 스무 칸을 "같음"으로 맞추고, 그다음 CuCu 프롬프트로 ~/.cucu/skills에 푼다. CuCu 위치는 아직 비교 표에 없으므로(P#275) 그곳에는 skill 폴더 열 개가 있는지만 본다. 스무 칸이 모두 "같음"이면 agent를 닫았다가 다시 연다. SHA-256은 적어 둔다. 팀이면 모두 같은 SHA-256의 키트를 쓴다.

이럴 때는

  • 표에 "다름"이 있다. 예전에 설치한 같은 이름의 skill이 있다는 뜻이다. AI가 예전 것을 백업하고 바꿀지 물으면 바꾸라고 답한다. 예전 skill을 계속 써야 한다면 이 키트로 진행할 수 없다.
  • 표에 "없음"이 남는다. AI가 보여 준 빠진 파일과 오류를 보고 원인을 해결한 뒤 같은 프롬프트를 다시 넣는다.
  • 키트가 새로 나왔다. 같은 방법으로 다시 설치한다. 진행 중인 프로젝트라면 팀 모두가 같은 키트로 바꾼다.
  • Codex로 구현하고 싶다. 그때는 Claude Code가 읽기 전용으로 리뷰한다. Codex 안에서는 GitHub 명령이 실패할 수 있다. 그러면 AI가 로그인 상태와 실행 환경을 확인한다. 로그인이 안 됐으면 로그인한다. 샌드박스가 네트워크나 키체인을 막았으면 다시 로그인하지 않고, 샌드박스 밖 실행을 요청하거나 사람이 터미널에서 돌릴 명령을 알려 준다. 순서는 Codex를 주 agent로 쓰기에 있다.
