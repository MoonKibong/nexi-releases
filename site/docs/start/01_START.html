프로젝트 시작

읽기 안내 — 누가: 혼자 하면 그 사람, 팀이면 PM · 언제: 고객의 요구사항 문서를 받았고 저장소가 아직 없을 때 · 읽은 뒤: 저장소와 작업 규칙을 만들고, 팀이면 팀원이 저장소를 받게 한 뒤 요구사항으로 간다.

빈 폴더에서 /nexi-init 하나로 시작한다. AI가 비공개 GitHub 저장소, 작업 규칙을 적은 AGENTS.md, 문서 폴더, 요구사항 원문 파일을 만들고 첫 commit을 한다. 만들어지는 파일은 산출물 참조에 있다.

예제는 1인 Step 1과 5인 Step 1이다.

순서

  1. 폴더를 만든다. 그 폴더에서 Claude Code를 연다.
mkdir <프로젝트 이름>
cd <프로젝트 이름>
claude
  1. 요구사항과 함께 /nexi-init을 넣는다. 팀이면 이름 뒤에 team을 붙인다(/nexi-init <이름> team). 혼자 하는지 팀인지에 따라 이후 모든 skill이 다르게 움직이므로 처음에 정한다.
/nexi-init <프로젝트 이름>
요구사항 원문:
<고객의 요구사항 문서를 그대로 붙여 넣거나, 파일 경로를 적는다>

AI가 GitHub 로그인을 요청하면 브라우저에서 마친다. 설치할 도구가 있다고 하면 설치하라고 답한다.

  1. 결과를 본다. AI가 알려 준 GitHub 저장소가 열리는지, AGENTS.md에 작업 규칙 여섯 개가 있는지 본다. 팀이면 팀 규칙과 PM: 줄도 있어야 한다. 요구사항 원문은 docs/requirements/REQUEST.md에 그대로 들어간다.

팀으로 할 때

  1. AI가 팀원마다 이름과 GitHub 아이디를 물으면 알려 준다. AI가 아이디마다 GitHub에 등록된 이름을 보여 주면 맞는지 답한다. 다 모으면 AI가 표 전체를 보여 준다. 빠진 사람이 없다고 답해야 그 표가 AGENTS.md의 ## 팀에 들어가고, AI가 표의 아이디로 저장소에 초대한다. 이 표는 누가 팀에 있는지 알려 주기만 하고 권한은 정하지 않는다. PM은 PM: 줄로 정한다.
  2. 팀원은 초대를 받아들인 뒤 자기 터미널에서 저장소를 받고, 받은 폴더에서 Claude Code를 연다. 이후 프롬프트는 모두 이 폴더에서 넣는다.
git clone https://github.com/<PM 아이디>/<프로젝트 이름>.git
cd <프로젝트 이름>
claude
  1. git clone이 로그인 문제로 실패하면(비공개 저장소다), Claude Code를 열어 GitHub CLI 설치와 로그인을 부탁하고 git도 그 로그인을 쓰게 한 뒤 다시 받는다.

이럴 때는

  • 요구사항을 넣지 않았다. AI가 아무것도 만들지 않고 요구사항 글이나 파일 경로를 달라고 한다. 넣고 다시 부른다.
  • 중간에 끊겼다. 같은 프롬프트를 다시 넣는다. 이미 만든 저장소, 라벨, 파일, commit, 초대는 다시 만들지 않는다.
  • 코드가 이미 있는 저장소다. /nexi-init은 있는 파일을 덮어쓰지 않고 빠진 NEXI 파일만 만든다. 이미 commit 이력이 있으면 새로 만든 파일을 commit하지 않고 목록으로 알려 준다. 로컬과 GitHub의 main이 다르면 push하지 않고 멈추고 차이를 보여 준다. 어떻게 할지는 사람이 정한다. 기존 코드를 먼저 돌려 보고 검사를 갖추는 순서는 레거시 코드가 있는 저장소에서 시작하기에 있다.
  • GitHub 명령이 실패한다. AI가 로그인이 안 된 것인지 샌드박스가 막은 것인지 가려 준다. 막힌 것이면 다시 로그인하지 않는다.
