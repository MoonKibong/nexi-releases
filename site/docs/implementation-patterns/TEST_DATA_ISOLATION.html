테스트 데이터 격리

읽기 안내 — 누가: 작업 계약을 쓰는 개발자, FDE · 언제: T#에서 이 문제를 풀 방법을 정할 때 · 읽은 뒤: 적용 전 결정을 고객·기술 책임자와 정하고, 반드시 지킬 조건을 수용 기준과 테스트에 넣는다.

해결하는 문제

테스트, agent 실행, 로컬 개발이 운영 환경이나 공용 개발 환경의 데이터·자격증명·외부 시스템을 건드리지 않게 한다.

반드시 지킬 조건

  • [보안] 필수 격리 설정이 빠지거나 자원 신원을 확인하지 못하면, 운영 자원이나 공용 개발 자원을 대신 사용하지 않고 실행을 멈춘다.
  • [보안] 테스트 자격증명에는 허용한 전용 자원·namespace의 최소 권한만 준다. 운영 자격증명이나 기본 자격증명 탐색으로 대신하지 않는다. 허용한 신원 확인 호출 말고는 검증 전에 데이터에 접근하지 않는다.
  • [보안] test라는 이름만 보고 안전하다고 판단하지 않는다. endpoint, account, IAM 권한, namespace를 함께 검사한다.
  • 병렬 테스트는 서로 다른 데이터와 외부 자원을 쓰거나, 안전하게 하나씩 순서대로 돌린다(직렬화).
  • [보안] 실행마다 자원 소유권과 namespace를 기록한다. 정리 작업은 그 실행이 소유한 자원만 대상으로 한다. 소유권을 확인할 수 없으면 지우지 않고 보고한다.
  • [보안] 실제 고객 데이터와 운영 자격증명을 fixture·로그·스크린샷에 넣지 않는다.
  • [보안] 테스트 대상 애플리케이션뿐 아니라 fixture 생성, migration, 정리 작업, agent가 직접 부르는 도구에도 같은 경계를 적용한다.

검증 계약

  • 환경변수를 지웠을 때, 운영 endpoint를 별칭으로 가리켰을 때, 허용되지 않은 account나 권한이 넓은 자격증명을 쓸 때 모두 금지된 데이터 접근과 외부 효과가 일어나지 않는다. account 확인에 필요하며 허용된 신원 확인 호출은 이 금지와 구분한다.
  • 서로 다른 표식 데이터를 쓰는 두 실행을 병렬로 돌리고 하나를 중단·정리해도, 다른 실행의 데이터·파일·queue는 그대로 남고 서로 섞이지 않는다.
  • 실패하거나 중단된 뒤 남은 자원을 실행 기록과 대조할 수 있고, 그것을 정리하는 절차를 확인한다.
  • 소유권 기록이 없는 자원은 정리 작업이 지우지 않고 보고한다.
  • 합성 비밀값을 넣고 로그·fixture·스크린샷을 검사하면 금지 항목이 나오지 않는다.

출처와 제한

이 패턴은 일반적인 테스트 자원·데이터 격리 원칙에서 나왔다. 기준은 반드시 지킬 조건과 검증 계약이다. 특정 구현의 코드를 그대로 가져다 쓰지 않고, 참고할 구현도 이 문서의 검증 계약을 통과해야 쓴다.
