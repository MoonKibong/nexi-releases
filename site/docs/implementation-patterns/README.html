구현 패턴

구현 패턴

읽기 안내 — 누가: T#의 구현 방법을 정하는 개발자, FDE · 언제: 로그인, 목록 조회, 고객 간 데이터 격리 같은 구현 문제를 어떻게 풀지 정할 때 · 읽은 뒤: 풀어야 할 문제에 맞는 패턴을 골라 작업 계약에 적용한다.

구현 패턴 자산은 여러 고객 프로젝트에서 반복되는 구현 문제를 풀 때 다시 쓴다. 작업 하나를 끝내는 절차는 작업 순환에 있다. 자산은 실제 T#에서 "로그인은 어떻게 만들 것인가", "목록을 어떻게 나눠 보여 줄 것인가", "다른 고객의 데이터를 어떻게 막을 것인가"를 정하는 데 쓴다.

사용하는 방법

NEXI 키트에도 같은 패턴이 들어 있다(nexi-contract/references/patterns/).

  1. 작업 계약서를 쓸 때 AI(nexi-contract)가 아래 자산 목록의 "적용 시점"을 그 작업의 이슈, 요구사항 결정 문서(REQ-CONTEXT), 산출물과 맞춰 해당할 수 있는 패턴을 보인다. 앞서 수용된 작업이 같은 판의 패턴을 적용으로 정했으면 묻지 않고 따르고, 그렇지 않은 패턴마다 적용할지, 해당하지 않는지, 예외를 둘지 사람에게 묻는다. 해당 여부는 작업마다 따로 본다.
  2. 적용하는 패턴의 적용 전 결정은 고객 정책이다. 요구사항 결정 문서에서 정하고, 작업 계약서에서 정하지 않는다. 요구사항을 정할 때 AI(nexi-requirements decide)가 해당할 수 있는 패턴의 적용 전 결정을 결정이나 질문으로 올린다. 결정이 없으면 계약서를 쓰기 전에 요구사항 결정에 더한다.
  3. 반드시 지킬 조건 가운데 그 작업에 해당하는 것을 수용 기준으로, 검증 계약의 해당 항목을 검증 명령으로 옮긴다. 해당하지 않는 조건은 이유를 적는다.
  4. 고객 요구 때문에 조건 하나를 따르지 않아야 하면 계약서에서 그 조건을 빼지 않는다. 요구사항 결정에 패턴 예외로 남기고, 고객 측 결정자의 이름과 날짜를 받는다. [보안] 조건의 예외는 보안·데이터 담당자도 받아들여야 한다. 예외는 조건 하나에만 해당하고, 같은 패턴의 다른 조건은 그대로 지킨다.
  5. 기술스택 프로필은 구현 후보일 뿐이다. 아직 만든 프로필은 없다. 그동안은 프레임워크의 공식 보안 지침을 쓴다. 프로젝트가 실제로 쓰는 프레임워크·버전·보안 정책을 확인한 뒤 쓴다.
  6. 적용한 패턴 이름, 고른 프로필, 테스트 결과를 작업의 증거 파일 docs/evidence/T<N>.md에 남긴다.

자산의 상태를 읽는 법

표시 뜻
asset_type: contract, applies_to: technology-neutral (frontmatter) — 기술에 묶이지 않는 계약 어떤 언어·프레임워크를 쓰든 지켜야 하는 결과와 테스트 조건
"조건부 기술스택 프로필" 절 특정 프레임워크를 쓸 때의 구현 방향. 다른 스택에 그대로 적용하지 않음
"적용 전 결정" 절 고객 정책·규정·인프라에 따라 프로젝트마다 정해야 하는 값
"출처와 제한" 절 참고한 구현을 그대로 쓰지 않고 검증 계약을 기준으로 삼는다는 설명
[보안] (반드시 지킬 조건 앞) 지키지 않으면 보안·데이터 사고(권한 밖 접근, 다른 고객 데이터 노출, 비밀값 유출, 운영 데이터 손상)로 이어지는 조건. 예외는 보안·데이터 담당자도 받아들여야 한다
review_status: candidate 검토를 거쳐 reviewed로 올리기 전인 계약 초안
review_status: reviewed 보안·이식성·검증 계약을 검토하고 필수 수정을 반영한 계약. 보안 인증이나 운영 배포 승인은 아님. 프로젝트에 적용할 때 검증 계약으로 다시 확인

frontmatter의 status와 review_status는 서로 다른 상태를 나타낸다. status는 문서 메타데이터 규칙(내부 문서 docs/dev/WIKI_AUTHORING.md의 "메타데이터" 절)의 문서 수명주기 값(draft 초안, 사용 중, 대체됨)이다. review_status는 자산 검토 상태(candidate, reviewed)다. 그래서 한 계약이 status: draft이면서 review_status: reviewed일 수 있다.

계약은 독립 검토와 Practice Lead 승인을 거친 뒤 candidate에서 reviewed로 올린다. 독립 검토는 그 계약을 쓰지 않은 다른 agent나 사람이 한다. 결과는 그 계약의 frontmatter review_status에 남긴다. 검토 기록은 수행사가 보관하며, 요청하면 제공한다.

새 자산은 _PATTERN_TEMPLATE.md로 시작한다. 구현보다 계약을 먼저 쓴다. 실제 프로젝트에서 충분히 검증된 구현만 따로 기술스택 프로필로 만든다.
