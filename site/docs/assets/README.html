NEXI 키트

NEXI 키트

읽기 안내 — 누가: NEXI로 프로젝트를 하려는 사람 · 언제: 프로젝트를 시작하기 전, 키트가 새로 나왔을 때 · 읽은 뒤: 키트를 내려받아 Claude Code와 Codex에 설치한다.

NEXI 키트는 요구사항 분석부터 작업 계약서, 구현, 리뷰, 병합, 마무리까지 시작하기의 모든 단계를 프롬프트로 진행하는 skill 열 개다. Claude Code가 문서와 코드를 쓰고, 구현하지 않은 쪽(보통 Codex)이 읽기 전용으로 리뷰한다. 저장소, 이슈, PR은 GitHub를 쓴다. GitLab 같은 다른 서비스는 아직 지원하지 않는다. 고객 저장소에 들여오기 전에는 고객의 보안, 데이터 처리, 도구 정책을 확인한다.

NEXI 키트 내려받기

현재 공개 다운로드는 준비 중이다. Rust 전환과 플랫폼별 검증을 마친 키트를 공개 배포할 예정이다. 키트를 받은 뒤 아래 설치 절차를 진행한다.

키트에는 skill 열 개와 설치 안내(INSTALL.txt)가 들어 있다. nexi-contract 폴더에는 구현 패턴도 들어 있다. skill끼리 서로의 폴더에 있는 파일(판정 형식, 수용 조건, 변경 지문 스크립트, 구현 패턴)을 읽으므로 열 개를 같은 skill 폴더에 함께 설치한다.

skill 쓰는 곳 하는 일
nexi-init Claude Code 개발 도구를 확인하고 GitHub 저장소와 작업 규칙(AGENTS.md)을 만든다. 팀이면 팀원을 초대한다
nexi-requirements Claude Code 요구사항을 분석해 질문을 만들고, 답을 받아 결정 문서를 쓰고, 사람의 승인을 기록한다
nexi-backlog Claude Code 요구사항을 하루 안에 끝낼 작업으로 나누고 순서를 정한다. 다음 작업 고르기, 나누기, 변경, 담당 바꾸기도 한다
nexi-contract Claude Code 작업 하나의 작업 계약서를 쓰고 사람의 승인을 기록한다
nexi-design Claude Code 화면의 디자인 기준(색, 글꼴, 간격, 구성 요소, 화면별 상태)을 쓴다
nexi-implement Claude Code 승인된 작업 계약서대로 구현한다. 새 검사가 먼저 실패하고 나중에 통과하는 것을 증거로 남긴다
nexi-review Codex, Claude Code 구현하지 않은 agent(보통 Codex)가 읽기 전용으로 리뷰하고 APPROVE, REVISE, BLOCK 중 하나로 판정한다. 판정 기록은 Claude Code가 남긴다
nexi-merge Claude Code 리뷰받은 변경을 main에 넣고 이슈를 닫는다. 중간에 끊겼으면 같은 프롬프트를 다시 넣어 이어 간다
nexi-finish Claude Code 저장소를 새로 받은 사본에서 설치부터 lint까지 돌려 최종 보고를 쓰고, 사람이 써 볼 앱을 띄운다
nexi-run Claude Code 선택 기능. 구현, Codex 리뷰, 판정 기록을 되풀이한다. APPROVE, BLOCK, 연속 세 번째 REVISE에서 멈춘다. 병합은 하지 않는다

설치. 내려받은 뒤 Claude Code를 열고 이렇게 넣는다.

~/Downloads/nexi-kit.zip 안의 INSTALL.txt를 읽고 그대로 설치해라.

AI가 zip의 SHA-256과, skill마다 두 설치 위치(Claude Code, Codex)의 비교 표를 보여 준다. 스무 칸이 모두 "같음"이면 Claude Code와 Codex를 닫았다가 다시 연다. 같은 이름의 예전 skill이 있으면 AI가 바꿀지 묻고, 바꾸라고 하면 백업한 뒤 바꾼다. 자세한 것은 준비에 있다.

skill마다 넣는 값, 하는 일, 멈추는 경우, 다음 프롬프트는 skill 참조에 있다.

키트를 고칠 때(저장소 관리자). skill 원본을 고친 뒤 make kit로 zip을 다시 만든다. make test가 zip과 원본이 같은지 검사한다.
